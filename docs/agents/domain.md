# Domain Docs

Single-context repo.

## Before exploring, read these

- **`GLOSSARY.md`** at the repo root.
- **`docs/adr/`**: read ADRs that touch the area you're about to work in.

If any of these files don't exist, proceed silently.

## File structure

```
/
├── GLOSSARY.md
├── docs/adr/
└── backend/
└── frontend/
```

## Use the glossary's vocabulary

When your output names a domain concept, use the term as defined in `GLOSSARY.md`. If the concept isn't there yet, note it for `/domain-modeling`.
