# Календарь звонков


[![hexlet-check](https://github.com/SadyrbayevAsset/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/SadyrbayevAsset/ai-for-developers-project-386/actions)

Сервис для бронирования времени звонков. Владелец публикует доступные типы встреч, а гости выбирают удобный слот и записываются без регистрации.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers

## Сценарий использования

### Владелец календаря

1. Открывает приложение.
2. Создаёт тип встречи: указывает название, описание и длительность (например, «Введение в продукт», 30 минут).
3. Видит список всех созданных типов встреч.
4. Просматривает список предстоящих записей по всем типам встреч.

### Гость

1. Открывает приложение без регистрации.
2. Видит список доступных типов встреч.
3. Выбирает подходящий тип.
4. Видит календарь свободных слотов на ближайшие 14 дней.
5. Выбирает свободный слот и оставляет своё имя и контакт.
6. Получает подтверждение записи.

## Ограничения и правила

- Владелец календаря один и задан заранее.
- Авторизация, личные кабинеты и интеграции с внешними календарями не реализуются.
- Окно записи занимает 14 календарных дней, начиная с сегодняшнего дня.
- Часы работы владельца и часовой пояс фиксируются в спецификации.
- Длительность слота совпадает с длительностью типа встречи.
- Одно и то же время нельзя занять дважды, даже разными типами встреч. Частичные пересечения тоже запрещены.
- Следующая встреча может начинаться в момент окончания предыдущей.
- Правила пересечений должны соблюдаться даже при одновременных запросах.
- Данные хранятся в памяти процесса. После перезапуска контейнера все записи сбрасываются. Это касается как локального запуска, так и деплоя на Render.

## Стек технологий

- **Backend:** Node.js + Fastify + TypeScript
- **Frontend:** React + Vite + TypeScript + TanStack Query
- **API-контракт:** TypeSpec
- **Генерация клиента:** TypeSpec → OpenAPI → TypeScript SDK
- **Тесты:** Vitest
- **Контейнеризация:** Docker

## Требования к API и генерации клиента

- API описывается через TypeSpec.
- Из TypeSpec генерируется OpenAPI-спецификация.
- На основе OpenAPI генерируется клиентский SDK для фронтенда.
- Серверная часть реализуется в соответствии с контрактом и проверяется тестами.

## Установка

```bash
git clone https://github.com/SadyrbayevAsset/ai-for-developers-project-386.git
cd ai-for-developers-project-386
npm run install:all
```

## Деплой

Приложение развёрнуто в облаке и доступно по публичной ссылке:

**https://REPLACE_WITH_RENDER_URL.onrender.com**

> Замените `REPLACE_WITH_RENDER_URL` на реальный URL после деплоя.

### Локальный запуск через Docker

```bash
docker build -t calendar-app .
docker run -p 3000:3000 -e PORT=3000 calendar-app
```

Приложение стартует внутри контейнера автоматически. Порт берётся из переменной окружения `PORT`.

### Подключение MCP-сервера Render

Для автоматизации деплоя через агента используется MCP-сервер Render.

1. Создайте API-ключ в настройках Render: https://dashboard.render.com/settings/api-keys
2. Скопируйте файл шаблона:
   ```bash
   cp opencode.json.example opencode.json
   ```
3. Подставьте ключ через переменную окружения:
   ```bash
   cp .env.example .env
   # отредактируйте .env, добавив RENDER_API_KEY
   ```

Секреты не коммитятся в Git. В репозитории лежат только шаблоны `opencode.json.example` и `.env.example`.

## Использование

Запуск backend и frontend в режиме разработки:

```bash
npm run dev
```

Backend будет доступен на http://localhost:3000, frontend — на http://localhost:5173.

Прогон всех проверок:

```bash
npm run check
```
